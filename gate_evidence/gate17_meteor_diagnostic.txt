--- STEP 2: REFERENCE SET CONSTRUCTION AUDIT ---
Question: Does the per-video reference set passed to the scorer include all ground-truth sentences
for that video's events, or only one target reference?
Finding:
- In the PREVIOUS evaluation implementation (Run 1 & Run 2): The code constructed references as
  `other_refs = [s for s in gt_sents if s != ref_target][:2]` and passed `[ref_target] + other_refs`.
  This bundled up to 3 disparate events from different time intervals into the reference list.
  Because NLTK's `meteor_score(references, hypothesis)` evaluates against ALL provided references and
  selects the MAXIMUM match, generic high-frequency words received unearned unigram and synonym credit.
- In the OFFICIAL ActivityNet Captions DVC Protocol (`densevid_eval3.py`): Each temporal proposal is
  evaluated strictly against the specific ground-truth event it matched at tIoU >= threshold.
  Multiple references are ONLY valid when multiple human annotators wrote descriptions for the SAME
  temporal segment (e.g. consensus testing), NOT by pooling sentences from distinct events.
- In the CORRECTED protocol (Gate 14 DEC-003): Reference sets are strictly single-event target references,
  eliminating cross-event reference contamination entirely.
